# 자동 검토 전체 입력 대조와 전송 검증

## 검증 대상

요청한 범위는 검토 모델의 차이가 아니라 **검토자가 판단에 사용하는 입력의 누락·변형·출처 혼동**이다. 공개 Codex `rust-v0.160.0`의 입력 생성 코드·회귀 스냅샷과 Pi의 실제 이벤트 및 공급자 전송 경로를 대조했다.

이번에는 `ModelRegistry.streamSimple()`의 인자 확인에 더해 다음 두 경계를 검사한다.

1. 실제 Pi 모델 공급자가 로컬 HTTP 시험 서버에 보낸 요청 본문을 직접 검사한다.
2. 실제 GLM 호출에서 검토 직전 입력과 HTTP로 전송하는 입력의 문맥·정책·조사 왕복 대화·도구 정의 해시를 비교한다. 요청·응답·헤더를 바꾸지 않는 관찰 코드이며, 기록에는 원문 대신 해시를 남긴다.

## 발견한 누락과 수정

수정 전 재현 검사에서는 두 시나리오가 실패했다.

- 뒤의 확장이 바꾼 개발자 지침이 검토자에게 전달되지 않았다.
- 최종 준비된 실행 인수와 승인 창의 구체적인 확인이 확장 재로드 후 복원되지 않았다.

별도 실제 Pi 축약 검사에서도 새 요약이 검토 문맥에 나타나지 않는 실패를 재현했다.

대조 과정에서 함께 보완한 내용:

- 도구 결과를 수정 가능한 중간 훅에서 수집하던 방식을 최종 이벤트 수집으로 바꿨다. 성공·실패, 구조화된 값과 중첩 출처도 보존한다.
- 권한 프로필을 해시로만 전달하던 경로에 현재 실제 프로필을 함께 제공한다.
- 승인 창의 확인을 작업 해시만으로 표시하지 않고 정확한 작업·선택·범위와 함께 기록한다.
- 실제 질문 API의 응답을 출처가 확인된 답변으로 기록하고, 늦게 도착한 이전 세션의 답변과 취소된 응답은 승인 근거로 넣지 않는다. 새 답변은 이전 승인 상태에서 시작한 대기 검토를 무효화한다.
- 재승인이나 직접 사용자 셸 지시를 문맥에 추가할 때 이전 해시까지 다시 해시하던 계산을 수정했다. 전송된 문맥만으로 해시를 다시 계산해 검증할 수 있다.
- 이전 평가와 최종 도구 증거는 세션의 `pi-codex-auto-review.context.v1` 기록으로 보존한다. 모델의 평가나 요약 자체는 사용자 승인이 아니다.

## 실제 전송 검증 방식

각 검토 요청에서 다음 조건을 확인한다.

- 전달된 정확한 작업의 해시가 인수·작업 디렉터리·출처 등 실제 필드와 일치한다.
- 문맥 해시가 전달된 사용자 지시와 증거 전체의 해시와 일치한다.
- 작업에 결합된 권한 해시가 제공한 실제 권한 프로필과 일치한다.
- 공급자에 선언한 검토 도구는 `inspect_file`·`inspect_directory`뿐이다.
- 공급자 호출 직전 문맥·정책·조사 왕복 대화·도구 정의 해시와 HTTP 본문에서 다시 얻은 네 해시가 요청별로 일치한다. 도구 호출의 이름·인수·호출 ID, 조사 결과와 연결 ID, 도구 설명과 매개변수 스키마까지 포함한다.
- 요청 수가 실제 검토 호출 수와 일치하며, 누락·중복·순서 변경이 있으면 통과하지 않는다.

GLM SDK 검증과 별도 프로세스로 실행하는 설치 패키지 CLI를 각각 관찰한다. SDK 쪽 기록만으로 CLI 전송까지 확인했다고 간주하지 않는다. 기존 실모델 증거 검증기도 두 경로의 전송 기록이 없는 결과를 거부하도록 강화했다.

## 차이를 숨기지 않는 경계

- JSON 포장 형식과 역할 배치는 서로 다른 SDK에 맞게 대응한다. Codex의 Rust 요청과 Pi HTTP 요청 전체가 바이트 단위로 같다는 뜻은 아니다.
- 경로·도메인 정보는 현재 Pi의 실제 승인 프로필이다. 존재하지 않는 OS 샌드박스를 있다고 전달하지 않으며, OS 격리 차이는 남는다.
- 비밀 환경값, API 키, 비공개 추론은 복제하지 않는다. 숨긴 환경값은 명시적으로 생략하며, 모델 인증 헤더는 검토 본문과 별도이다.
- 이 확장이 출처를 기록하기 전의 과거 Pi 사용자 역할 메시지는 실제 사용자 입력인지 확장이 생성한 문장인지 증명할 수 없다. 그 기록을 임의로 승인 근거로 승격하지 않는다. 이후 실제 사용자 지시로 명확히 승인하는 경로는 지원한다.
- 관찰하는 외부 도구 UI는 공개 `select`·`confirm`·`input` API다. 임의 `custom` UI나 외부 프로그램의 화면에서 일어난 클릭을 사용자 승인으로 추정하지 않는다.
- 연결 계정 메타데이터는 등록된 서버가 제공한 증거이며, 이 변경이 계정 소유권을 별도로 인증한다는 뜻은 아니다.
- 정상 SDK 경로 이후에 신뢰한 사용자 코드가 네트워크 요청을 임의 변경하는 모든 경우까지 막는 격리 기능은 아니다. 이번 전송 검사는 실제 사용한 OpenAI 호환 시험 공급자와 `pi-ollama-cloud` 경로를 확인한다.
- 원본 비교는 위 공개 고정 버전의 코드와 회귀 스냅샷에 근거한다. Codex의 비공개 서비스 내부 프롬프트나 현재 데스크톱 앱의 실제 서버 요청을 직접 수집해 비교한 것은 아니다.

검토 요청 총 15회에서 `inputDigest`, `policyDigest`, `conversationDigest`, `toolsDigest`를 각각 대조했다. 실제 읽기 전용 조사 후 두 번째 요청에 포함된 도구 호출·결과도 비교 대상이다. 정상 범위 작업과 보호 경로의 결정적 거부는 검토 모델을 호출하지 않는 기존 경로를 유지한다.

Windows·Linux x64·GitHub Actions 검증과 npm 배포는 이번에 실행하지 않았다. 변경은 설치된 npm `0.1.3`에 아직 포함되지 않는다.
