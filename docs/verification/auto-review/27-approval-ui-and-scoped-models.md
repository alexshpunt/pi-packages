# 승인 화면·모델 범위·자동 검토 개선

2026-10-04, `0.1.3` 이후 소스에서 승인 화면 설명, 자동 검토 동작, `/scoped-models` 연동, 영문 UI를 개선했다. 이 문서는 소스 변경과 실제 실행 근거를 기록하며 npm 새 버전 게시를 의미하지 않는다.

## 반영한 변경

| 요청 | 변경 |
| --- | --- |
| 승인 방식 설명 | [Codex 공식 승인 선택 화면](https://learn.chatgpt.com/docs/security-administration)의 영문 설명을 두 항목에 표시한다. 현재 항목을 선택 상태로 열고, 좁은 화면에서도 선택한 설명을 줄바꿈해 보여 준다. |
| 자동 검토 확인 | 선택한 승인 방식과 보조 모델이 실제 Pi 호출에 적용되는지 확인했다. 네트워크 명령의 검토 누락을 재현하고 수정했다. |
| 모델 목록 | Pi의 공개 `context.scopedModels`와 현재 사용 가능한 모델을 대조한다. 순서를 유지하고 사용 불가·중복 항목을 제외한다. 지정 범위가 없을 때만 전체 사용 가능 모델을 표시한다. |
| 영문 UI | 명령 자동완성 설명, 선택창, 도움말, 승인 대화상자, 검토 상태·알림의 고정 문구를 영어로 바꿨다. 사용자 입력이나 모델 응답의 언어는 강제로 바꾸지 않는다. |

`Use current Pi model`은 기존 `reviewModel: null` 선택을 유지한다. 보조 모델을 선택해도 주 모델은 바뀌지 않는다. 선택창을 연 뒤 모델이 현재 범위에서 사라지면 저장을 거부하고 기존 설정을 보존한다.

## 재현과 수정

기존 구현은 전체 사용 가능 모델을 읽고 `/scoped-models`를 무시했다. 실제 Pi 세션에 검토 모델 하나만 지정했는데도 선택창에는 범위 밖 모델을 포함한 네 항목이 표시됐다. 수정 후에는 현재 모델을 따르는 항목과 지정한 검토 모델만 표시된다. 해당 모델이 실제 승인·거부 요청을 받고, 승인한 파일만 변경되며 주 모델은 그대로 유지되는지 검사했다.

네트워크 검사에서는 스킴을 생략한 curl 주소와 설정 파일 안의 URL이 자동 검토를 생략하는 것을 재현했다. 허용 대조군으로 서버 접근을 확인한 다음 거부 결과를 제공해도 요청이 추가 도달했다. 명시적인 HTTP URL을 찾지 못하거나 별도 설정 파일이 지정된 명령은 검토하도록 수정했다. 자동 검토·사용자 승인 각각에서 허용 요청만 소유한 HTTP 서버에 도달하는지 확인한다. 허용 URL과 설정 파일을 함께 지정한 경우도 검사한다.

이 호스트의 curl이 지원하지 않는 `--url=…` 형식은 허용 대조군부터 실패했으므로 실행 효과의 검증 근거로 사용하지 않았다. 첫 전체 실행의 패키지 검사도 이전 한글 도움말 기대값 때문에 실패했다. 실제 배포 CLI의 영어 도움말과 한글 고정 문구 부재를 검사하도록 기대값을 수정하고 재실행했다.

## Codex와 대조한 범위

[공식 Auto-review 동작](https://learn.chatgpt.com/docs/sandboxing/auto-review)을 기준으로 다음 계약을 확인한다.

- 일반 허용 동작과 승인 요청을 구분하고, 자동 검토 모드에서는 별도의 검토 요청을 사용한다.
- 사용자 승인 모드에서는 검토 모델을 호출하지 않고 사용자 선택을 따른다.
- 선택한 보조 모델, 출력 한도, 취소 신호가 최종 공급자에 전달된다.
- 잘못된 평가·공급자 오류·시간 초과·취소·늦은 승인으로 실행하지 않는다.
- 위험·인가 기준, 거부 사유 전달, 3회 연속 또는 최근 50회 중 10회 거부 시 중단을 유지한다.
- MCP의 일반·엄격·필수 사용자 승인 경로와 호출별 승인 연결을 유지한다.

현재 Pi 구현에는 OS 샌드박스가 없다. 이미 승인된 셸 내부의 파일 접근이나 실행 중 네트워크 목적지 변경을 OS 수준에서 제한하지 않으며, Codex 전체 보안 경계나 독점 검토 모델의 판단과 동일하다고 주장하지 않는다. 일반 MCP 입력 폼·URL 인증 요청도 기존처럼 별도 인간 입력 UI 없이 자동 처리하지 않는다.

실모델의 일반 허용·보호 경로 거부는 검토자를 호출하지 않았고, 추가 승인·정책 거부·CLI는 검토자를 각각 1회 호출했다. 모든 사례에서 주 모델은 2회 호출됐으며, 실제 효과·감사 기록·키 비노출을 확인했다.
