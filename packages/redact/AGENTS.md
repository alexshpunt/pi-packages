## 1. Overview

This host-independent library masks credentials, private keys, and explicitly enabled personal information in presentation copies of text and JSON. Callers choose the output boundary; it neither intercepts I/O nor makes original data safe to disclose.

## 3. Core Behaviors & Patterns

- **Strict construction, observable normalization**: `normalizeRedactionConfig` returns frozen configuration plus issues; any invalid entry replaces that entire list with `[]`, and unknown keys produce issues. `createRedactor` rejects any user/host issue instead of silently accepting fallback lists. User rule IDs use unique `custom.*`, host rules use unique `host.*`; flags allow `i`, `m`, `s`, `u` once each, while the engine adds `d`/`g`. Invalid regexes and patterns matching the empty input are rejected. Diagnostics identify keys/indexes without echoing patterns, exception values, or raw regex parser errors. This is not a general regex complexity guarantee.
- **Instance scope**: Construction compiles configured rules, normalized exact-field names, exceptions, and selected PII into an immutable redactor. There is no process-global configuration, activation switch, or detection cache. `full` scans patterns, PEM, label-aware PII, and assignments; `context-free` omits assignments and label-dependent PII. Named-value scans run pattern/PEM/PII detection plus whole-string detection for a sensitive normalized name; they do not run assignment fallback. Built-in sensitive suffixes and configured exact names are separate routes.
- **Detect before cutting**: `scan` captures frozen detections from one full original text; `renderRange` intersects those ranges with a requested excerpt. It does not verify text identity: callers must render the same unchanged original, not a previously masked or edited string. Each range is half-open UTF-16, not UTF-8 bytes. Regex rules mask a nonempty participating `secret` group, otherwise the whole match. PEM detection masks through the matching END marker or to EOF when unterminated.
- **Assignment alternatives**: `detectAssignments` recognizes sensitive quoted bodies (including prefixes, raw/triple strings and doubled quotes), YAML block scalars by indentation, and ENV/INI-style values when the path hint matches `.env`, `.env.*`, or `env`/`ini`/`properties`/`cfg` extensions. Unclosed quotes extend to EOF. Path-hinted line values retain spaces/punctuation, stop at `#`/line end, and skip a value beginning with `$`. Generic bare values require an empty/`export`/quote/`{`/`,` prefix and skip null/boolean tokens, `$`/`[`/`{` starts, and values containing `(`. This is the text fallback, not tree-sitter parsing or identifier/reference protection.
- **Exceptions and masking**: `finishDetections` removes only a matching rule ID plus the entire original detected span; quoted assignment bodies compare without outer quotes and without escape decoding. Another rule's overlapping detection still applies. `maskRanges` then merges overlapping or touching spans. `hideValue` masks each line body with `[REDACTED]` when it fits, otherwise repeated `*`, preserving LF and trailing CR line endings without increasing UTF-16 length. Built-in output is idempotent; arbitrary custom rules may also match mask markers.
- **JSON boundary**: `redactJson` returns `{ value, maskedLocations }` without mutating the original. Keys and non-string scalars remain visible; a sensitive key masks its string value, but arrays/objects do not pass that sensitivity to descendants. Respect `toJSON`, and use own-property construction so `__proto__` stays data. `shouldPreserve(path)` bypasses the entire subtree, including serialization and masking, so use it only for intentionally visible structural positions. `stringScope: whole` preserves multiline detection; `line` scans lines separately. `textContent: context-free` affects only the `text` field of a `type: text` object, with sensitive-field masking taking precedence. Changed-location metadata is deduplicated by path/rule and contains no raw match.
- **PII selection and pipeline**: Empty `piiEntities` avoids catalog parsing/compilation. Enabled names are exact/case-sensitive and compile in catalog order once per redactor. `compilePiiRule` searches candidates, rechecks the original translated expression with sticky/indexed matching, applies original left-boundary rules, then context, entity filters, and validators. The email accelerator applies only when its catalog pattern text matches exactly; other patterns use regex search. Do not replace this with an unanchored match over a sliced candidate.
- **PII context and validators**: Weak and field patterns require a matching label within 160 UTF-8 bytes in the same field/statement. One preceding line is allowed only for whitespace/quote continuation after an assignment/label ending `=` or `:`. Context-free mode skips these patterns entirely. Validators normalize numerals and distinguish `false` (reject) from `undefined` (unverified but accepted); unknown validator names throw. IBAN matching tests complete token ends, prefers a checksum-valid exact country-format length, otherwise retains the first valid fallback, then resumes at the accepted end so adjacent values are not skipped. Production detection trims surrounding URL quotes and trailing VAT separators. `find()` is a compatibility search without label checks and excludes field patterns; it is not the production `detect()` contract. No NLP, model request, or network lookup is involved.
- **Regex/data compatibility**: Catalog Rust expressions pass through `translateRustRegex`, which explicitly translates Unicode classes/boundaries and LF-only anchors and rejects unsupported constructs. Custom user rules are ordinary JavaScript regexes, not Rust-translated rules. Node.js 22 lacks inline modifier groups; Unicode property classifications also depend on the runtime's Unicode version. Keep linear scanners for JWT, URL passwords, webhook URLs, PEM, assignments, and the catalog email accelerator; naive regex substitutions can reintroduce quadratic work. Generated PII data is shipped as string constants rather than runtime JSON reads/imports for host-loader compatibility. Modify its source/generator, not generated constants by hand.

## 4. Conventions

- Detection metadata uses only `{ start, end, ruleId, kind }`; JSON metadata uses `{ path, ruleId }`. For example, `piiRuleId("EMAIL_ADDRESS")` is `pii.email-address`. Never add captured secret values to diagnostics or metadata.
- Keep external catalog fields such as `requires_context` unchanged and adapt them at typed boundaries. Share numerical/checksum helpers under `src/pii/validators/`; region-specific rules stay near their validators rather than leaking into JSON rendering.
- Source uses strict ESM TypeScript, `.js` relative imports, readonly interfaces, and frozen public configuration/scan objects. This package has no Pi dependency or runtime dependencies; host-specific legacy behavior belongs in the consuming adapter.
- Preserve the port's documented limits: UTF-16 offsets differ from Rust byte offsets, text fallback lacks syntax-aware exclusions, custom regex behavior can differ, and masking is not a guarantee that every secret or personal datum is detected.
