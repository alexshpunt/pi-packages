# Ollama Cloud Effect v4 리팩토링 검증

검증한 범위에서 기존 공개 계약을 유지하면서 비동기 실행을 Effect `4.0.6`으로 옮겼습니다. 전체 테스트 379개, 오프라인 진단 54개, 변경 전후 설치본의 세 가지 활성화 상태 비교와 PTY 검증이 통과했습니다. 실제 모델 요청은 변경 전 50회·변경 후 50회 모두 검증 조건을 충족했습니다. 다만 생성 응답의 완전한 동일성을 뜻하지 않으며, 명시적인 추론 끄기는 이번 실서비스 검증에서 확인하지 못했습니다.

- 작업 브랜치: `refactor/pi-ollama-cloud-effect-v4`

- 변경 후 실서비스 시작: `2026-10-23T16:14:01.645Z`

## 변경한 경계

[공통 코드 구조 규칙](../../../docs/code-organization.ko.md)에 따라 기존 기능별 소유권을 유지했습니다. 모든 파일에 같은 폴더나 서비스 형태를 강제하지 않았습니다.

| 경계 | 변경 | 보존한 계약 |
| --- | --- | --- |
| HTTP·CLI 채팅 | `Effect.acquireUseRelease`로 타이머·취소 구독·임시 디렉터리 정리 | 응답 본문까지의 제한 시간, 호출자 신호·옵션, 원래 오류 표현 |
| 계정 | `Semaphore`로 계정 선택 직렬화, 잔액 조회 Effect 조합 | 세션 고정·순환·구매 크레딧 보호·실패 분류·공유 잔액 작업의 독립 수명 |
| 캐시·웹 | 공유 작업과 구독자 수명 분리, 마지막 구독자 종료 시 중단 | 인증별 공유, 세대별 발행, 이전 항목의 식별자 기반 삭제, 페이지·출력 상한 |
| 모델·사용량 | Effect 기반 요청·갱신 흐름, 회복 가능한 검증 오류 | 정확한 모델 ID, 카탈로그 복원·재시도·추론 정책, 사용량 반환 형식 |
| 저장·표시 | Effect 종료 경로에서 정리 | 파일 잠금 안의 동기 갱신, 저장 형식·권한, 폴링 주기, stale 결과 차단 |
| Pi·CLI 소비자 | 기존 Promise 진입점 유지 | 공급자·도구·명령 이름, 기존 함수 인수와 결과, host peer 경계 |

`shared/effects.ts`는 오류 원본을 유지하는 변환과 취소 연결만 담당합니다. 순수 정책·렌더링·생성 스냅샷은 바꾸지 않았으며, 새 재시도·요청 제한 정책도 추가하지 않았습니다.

추가한 11개 테스트는 Effect 오류·취소·응답 본문 정리·구독 해제와 50회 실행기의 요청 예산·중단·재실행 거부를 확인합니다. 기존 생성기 테스트는 새 운영 의존성을 임시 소비자에 준비하도록 수정했으며, 기존 동작 단언은 완화하지 않았습니다.

린트 경고 2개와 안내 2개는 변경 전후 동일하게 남아 있습니다. 검사 종료 코드는 0입니다.

### 실서비스 요청과 전후 비교

모델은 `glm-5.3-flash:cloud`로 고정했습니다. 단일 응답 10회, 문맥 유지 10회, thinking 설정 생략/low 10회, 등록된 웹 도구 호출과 후속 응답 20회로 실행했습니다. 모델 후속 요청도 횟수에 포함했습니다.

| 실제 전송 | 변경 전 | 변경 후 | 합계 |
| --- | ---: | ---: | ---: |
| 모델 | 50 | 50 | 100 |
| 검색 | 1 | 1 | 2 |
| 페이지 fetch | 1 | 1 | 2 |
| 잔액 | 1 | 1 | 2 |
| 모델 상세 | 1 | 1 | 2 |
| 전체 HTTP 요청 | 54 | 54 | 108 |

- 양쪽 모두 50개 사례가 통과했고, 차단된 추가 요청은 0회였습니다.
- 사례별 모델 ID·출력 토큰 상한·reasoning 전달값·tool choice·종료 사유·도구 이름은 모두 일치했습니다.
- 캐시 재사용은 양쪽 각각 10회 확인했으며 추가 전송이 없었습니다.
- 검색 도구 호출 5건의 반환 thinking 블록 유무는 달랐습니다. 이 구간의 `reasoning_effort`는 양쪽 모두 생략되어 있었습니다. 이를 추론 끄기 성공으로 해석하지 않으며, 이 관찰만으로 차이의 원인을 확정하지 않습니다.
- 오프라인 모델 진단은 지원 모델에서 `off → reasoning_effort: "none"`이 최종 요청에 적용되는 경로를 별도로 검사했습니다.

실서비스 검증 후 README의 초기 “off/low” 표현을 실제 전송에 맞게 “설정 생략/low”로 정정했습니다. 이후 운영 코드는 변경하지 않았습니다.

## 확인하지 않은 범위

실제 서비스에서 여러 계정의 한도 도달·키 거부·모델 거부나 통신 장애를 유발하지 않았습니다. 이 경계는 기존 모의 테스트로 검증했습니다. 다른 모델, Node.js 22.19, 다른 Pi 버전, 장기간 부하·성능 변화는 이번 실행으로 입증하지 않았습니다. 실제 응답의 토큰 수·문장·thinking 블록은 전후 동일성 기준에서 제외했으며, 완전히 같은 응답을 보장하지 않습니다.
