## 1. Overview

This extension bridges Pi to the Computer Use runtime already installed by Codex Desktop. It owns host integration, not the automation engine, OS isolation, runtime installation, or remembered app/browser permissions.

## 2. Ownership Map

### Stable Ownership Boundaries

- **Runtime selection and launch**: Start in `src/runtime.ts` and `src/platform.ts` for discovery, then `src/connection.ts` for the child environment and MCP handshake. Never bundle, copy, download, or substitute the private runtime. Preserve explicit unavailable/simulated states and Chrome-only browser exposure. Verify the discovered plan, enabled surfaces, and `/computer-use status`; a found runtime is not a successful app operation.
- **Session and tool lifetime**: Start in `src/index.ts` for server replacement and `src/tools.ts` for registration and call forwarding. One shared runtime serves both feature switches; old connections must not clear a replacement. Only `js` and `js_reset` are model-visible. Check tool visibility after start, failure, restart, and both-off settings, plus turn metadata in the bridge log.
- **Runtime approval requests**: Start in `src/elicitation.ts` for classification, UI choices, and wire responses; `src/active-call.ts` binds the current sequential call's context and signal. Preserve the narrow automatic empty-form exception and decline unsupported input surfaces. Verify accepted, declined, cancelled, no-UI, and persistent-choice responses—not merely dialog rendering.
- **Preferences and diagnostics**: Start in `src/settings.ts` for the strict two-flag schema and `src/commands.ts` for idle-gated changes. Prerequisite behavior belongs in `src/install.ts` and `src/browser-checks.ts`. Check `/computer-use-check` and the saved preference separately from runtime readiness; `missing`, `unverified`, `skipped`, and `user-owned` must not become success.

## 3. Core Behaviors & Patterns

- **Discovery order**: `discoverRuntime` accepts macOS and Windows; Linux/other platforms return unavailable. Prefer the newest numerically sorted, enabled `cua_repl` plugin-cache `.mcp.json` with an existing command file (the file check is bypassed only for simulation). Only macOS falls back to an app bundle. An explicit app-path override replaces default candidates; a known different bundle ID is rejected. The fallback validates the manifest, node, node_repl, launcher, and module directory. Service-app lookup tries `SKY_CUA_SERVICE_PATH`, then `CODEX_HOME/computer-use`, then the copy inside installed `@oai/sky`; it never copies that app. Windows implementation/simulation is not evidence of live Windows verification.
- **Environment boundary**: `composeEnvironment` starts from an allowlisted host environment, overlays the plan, derives `CUA_REPL_ENABLED_SURFACES` in browser/computer order, and filters `NODE_REPL_TRUSTED_SERVICES` to enabled `browser`/`sky` keys. Absent or malformed trusted-service JSON is omitted so the launcher computes it. When browser use is enabled, force `BROWSER_USE_AVAILABLE_BACKENDS=chrome`, even if Desktop's plan advertises more. `StdioTransport` uses `inheritEnv: false`; do not replace this with wholesale host-environment inheritance.
- **Startup and restart**: The extension factory registers handlers but starts no server. Session start loads settings and starts the shared connection only if a feature is on. Connection startup initializes MCP with form elicitation and lists tools; a tools/list failure closes the client. Startup/discovery failures leave tools hidden and report a problem. Unexpected-close handlers check `connection === opened` before clearing state, so stale connections cannot remove a replacement. Pi cannot unregister tools, so every previously exposed missing name is re-registered as a hidden error stub. The visible set is the intersection of `EXPOSED_TOOLS`, plan-enabled names, and the server catalog; `turn_ended` and module-path management remain internal.
- **Settings are preferences**: Missing settings means both flags on without creating a file. Existing settings must contain exactly `computerUse` and `browserUse` booleans; invalid/unreadable data disables both for the session, and commands refuse to overwrite it. Changes wait for idle, save through a unique `wx`/`0600` temporary file plus rename/cleanup, then restart the runtime. A saved switch is not rolled back when startup fails. Changing either switch clears REPL variables and app/tab bindings for both surfaces; both off starts no server.
- **Call identity and output**: Bridged tools execute sequentially and record an `ActiveCall`; `finally` clears it only if it is still the same call. Forward caller cancellation and call/session/thread/turn metadata, with automatic-review flags false. Calls use no host request timeout (`timeoutMs: 0`); runtime/tool timeout behavior remains separate. Return model text/images and runtime `_meta`. Long text is middle-truncated at the plan's token limit times four bytes; full text is saved best-effort to an owner-only temporary file, images remain, and the path or save failure is disclosed. These output files are not automatically removed by the bridge.
- **Turn completion**: `TurnTracker` spans `agent_start` to `agent_settled`, or begins on demand for an out-of-run call. Aborted runs produce `Interrupt`; completed/error runs produce `Stop`. `agent_end` also detects aborts when the pre-settle event is skipped. Settling clears the turn before one internal `turn_ended` request, sent asynchronously with a 120000ms timeout; failures are logged, not promoted to tool success. Shutdown waits at most 3000ms for a pending notification before closing the connection (transport close timeout 5000ms). MCP cancellation may leave JavaScript running until completion/runtime timeout; do not promise immediate OS-level interruption.
- **Approval alternatives**: Automatic acceptance requires a real object schema with empty `properties`, `tool_name=js`, `connector_id=node_repl`, `codex_approval_kind=mcp_tool_call`, and neither sensitive-action nor user-input flags. The strict-review flag alone does not exclude this special user-reviewer path. Combined runtime/call cancellation is checked before automatic acceptance. URL mode, browser sign-in, email OTP, and unsupported forms decline with a reason. Other requests need UI; print/JSON mode declines. Supported forms collect scalar text/number/boolean or enum/oneOf values with the implemented length/range checks, not arbitrary JSON Schema validation. Dismissal is cancellation. Session/always persistence is returned only when the runtime offers that choice; the bridge does not store grants. Decline notes attach to the active call's result.
- **Checks are not passive discovery**: `checkPrerequisites` can execute Desktop's installed setup script by default on a real runtime plan, then separately validate node/version/imports/node_repl; temporary import links are removed in `finally`. A setup failure matching a missing launcher is `unverified`, not a pass; independent runtime checks still run. Chrome checks prefer the newest installed diagnostic scripts and use file checks only when the plugin diagnostics are absent. Simulation yields unverified/skipped checks, and unrecognized diagnostic failures remain unverified. Login, subscription, and OS permissions retain user-owned checks. These paths do not install or download a runtime.
- **Logging limits**: `BridgeLog` rotates around 5 MiB, clips long lines, and cannot fail the bridge. It recursively masks values under secret-looking keys, but raw string payloads and arbitrary page/app text are not comprehensively redacted. Do not treat traffic logs as safe to publish.

## 4. Conventions

- Preserve the server's descriptions, annotations, and namespace instructions; add Pi-specific restrictions through `promptGuidelines` and `prepareLoadout`. Object schemas receive `properties: {}` when absent. Keep initial-entry/reset/compaction guidance aligned with actual supported surfaces, not Desktop-only examples.
- Use discriminated outcomes such as `RuntimeDiscovery.kind` and `SettingsLoadResult.source` rather than throwing away unavailable/invalid context. Return tool failures through `BridgeToolResult` with `isError`, `durationMs`, and optional `cancelled`; do not convert a missing connection into an empty success.
- Keep protocol constants and conversions centralized (`buildCallMeta`, `responseForChoice`, `hookEventNameFor`). For example, persistent approval uses `_meta.persist`, while turn notification uses `hook_event_name`; these are external wire keys, not naming preferences.
- Source uses strict ESM TypeScript with `.js` relative imports. Environment/runtime ownership stays in runtime/connection modules; settings panels call command-owned setters rather than starting child processes themselves.
