# 변경 이력

## [Unreleased]

### 새로워진 것

- Pi의 Windows `powershell` 도구를 `bash`처럼 보호합니다. Codex에서 옮긴 리터럴 PowerShell 문법, cmdlet·별칭의 경로·네트워크 분류, 별칭의 문서상 이름까지 포함한 내부 명령 기준 규칙 대조, 읽기 검토 재사용, 셸을 밝힌 검토 증거를 제공합니다. 보호된 도구는 비활성 상태로 등록되므로 실행 여부는 계속 `defaultTools`나 `--tools`가 정하며, 보호 시작도 더는 이 도구를 제외하지 않습니다.

### 해결된 것

- MCP 취소·시간 초과 신호를 유지하고 실패하거나 취소한 요청의 추적 상태를 해제합니다.
- 일반 설치와 Off 모드에서도 Pi의 셸 탐색과 셸·이미지 설정을 유지합니다.
- Windows: `C:\tmp`를 기본 쓰기 루트로 보지 않습니다(`excludeSlashTmp`는 영향이 없습니다). Git Bash·MSYS2·Cygwin의 `/c/...` 같은 드라이브 경로를 대응해 보호 파일을 계속 거부하고, 다른 POSIX 절대 경로와 WSL 경로는 검토합니다. 파일 도구의 `/c/...`·`~\` 경로를 Pi와 같이 정규화하고, 규칙에서 `bash.exe` 래퍼와 Pi의 실제 셸을 인식하며, 역슬래시 구분자의 `.git` 메타데이터와 CRLF `gitdir` 포인터를 인식하며, 다른 호스트의 공유 경로는 승인 전에 해석하지 않습니다. 위치를 알 수 없는 셸 대상이 있으면 이전에 승인한 skill 패키지도 다시 검토하고, 신뢰한 `allow` 규칙도 그 명령을 승인하지 않습니다.
- macOS와 Windows의 대소문자·유니코드 정규화 차이, 그리고 Windows의 대체 데이터 스트림·장치 이름공간·예약 장치 이름·드라이브 상대 경로·로컬 관리 공유·끝의 점이나 공백·없는 구성 요소의 짧은 이름으로 보호 경로를 우회할 수 없습니다. 이런 경로는 거부하거나 `INVALID_PATH`로 실패하며, 허용 루트는 계속 정확히 비교합니다.
- 여러 단어로 된 `.env` 값을 포함해 크기가 제한된 조사 파일 원문을 발췌 전에 가립니다.
- 도움말·패키지 로딩 중 검토 DB를 만들지 않고 메모리 감사 기록을 제한합니다. 시작 실패와 감사 파일의 수동 정리 안내를 바로잡았습니다.

## [0.6.0] - 2026-10-20

### 달라진 것

- 보호 CLI와 SDK가 Pi 1.0.0 이상에서 시작합니다. 1.0.0·1.1.0이 아닌 Pi 버전도 더는 `UNSUPPORTED_PI`로 실패하지 않으며, 1.0.0 미만은 계속 거부합니다.
- 소스 코드, 이슈, 릴리스 노트를 [pi-packages](https://github.com/buYoung/pi-packages) 저장소로 옮겼습니다.

### 제거된 것

- npm 압축 파일에서 `docs/publishing.md`와 `docs/publishing.ko.md`를 뺐습니다. 릴리스는 pi-packages 저장소의 절차를 따릅니다.
