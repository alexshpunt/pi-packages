## 1. Overview

This extension reviews prepared Pi actions before delegation. Ordinary extension loading and guarded startup provide approval boundaries, not OS, filesystem, or network isolation.

## 2. Ownership Map

### Stable Ownership Boundaries

- **Execution.** `src/tools/controller.ts` binds/rechecks actions, `src/policy/index.ts` decides, and `src/tools/executor.ts` delegates. Check final arguments/options in `tests/integration/pi-tools.test.mjs`, `tests/unit/policy.test.mjs`, and `tests/execution/executor.test.mjs`.
- **Approval/evidence.** `src/approvals.ts` owns grants/UI, `src/reviewer.ts` requests, `src/review/context.ts` provenance/budgets, and `review/redaction.ts` masked copies. Check approvals/reviewer unit tests and `tests/integration/review-context.test.mjs`; the three reuse mechanisms are not interchangeable.
- **Startup/settings.** `src/startup.ts` implements `./startup`, consumed/disposed by `src/cli.ts`; `src/index.ts` wires it and `approval-settings.ts` persists settings. Factories register only; memoized initialization runs at session start/first use, or explicitly before guarded services/reload. Initialization failures stay failed until reload. Guarded initialization stops on errors. Ordinary delegates read effective Pi shell/image settings after binding, with explicit SDK options taking precedence. Check guard e2e, context-files unit, and approval-settings integration tests.
- **External calls.** `src/tools/mcp.ts` binds catalogs/transports; `external.ts` interprets annotations. MCP integration/external unit tests cover final `tools/call`. Host-internal runtime/config/auth imports need separate compatibility checks beyond the major-version gate.
- **Rules.** `src/policy/rules.ts` owns workers, synchronous evaluation, and shell wrappers; `rule-engine.ts`/`starlark/` implement the language. Check execpolicy/execpolicy-parity tests. Rule children are not ordinary tool execution.

## 3. Core Behaviors & Patterns

### Binding and deterministic policy

- Intercept bash at `operations.exec` after prefixes/shell options. An unset shell path stays unset for Pi execution; resolve evidence identity through the host resolver, with a deterministic unresolved marker on failure. Evidence omits sensitive env values but keeps names; execution retains original env, timeout, output callback, and signal. File review resolves the target but delegates prepared original parameters to Pi. Queue write/edit admission and execution by canonical path, separately from Pi's queue; delete only the task's own current entry.
- `createAction()` freezes canonical input/cwd/profile/policy identity. After admission, reject changed authorization/session/cwd/policy, reevaluate, and reject deny or changed delta/authority. Combine caller/controller/turn signals; direct user bash bypasses only the turn breaker. `PiExecutor.close()` aborts and settles active work.
- Default reads are broad; workspace/configured/temp writes are ordinary only in `workspace-write`, otherwise reviewable. Hard-protect control/settings/cache/rule files and deny writes to extension/trusted-code directories. Review writes to `.git`/worktree pointers, existing `.agents`/`.codex`/`.aws`, and project `.pi`; deny `.pi/guard` writes. `canonicalPath()` resolves missing targets through existing ancestors. Custom profiles retain baseline hard protections and project `.pi` review boundaries.
- Forbidden rules, protected paths, and denied domains precede allows. A prompt match defeats an allow; command-rule authority requires an allow for every command group and no `unboundTargets`. Match unsupported syntax/redirections as the real outer shell, not a supposedly safe inner prefix. Unknown operations or indirect destinations can require review, but analysis is not exhaustive interpreter/network enforcement.
- Without explicit additional permissions, `require_escalated` requests invocation-only `reviewed-command` authority unless a trusted rule already allows the action. Validate explicit deltas against absolute denies. Disabled approval categories prevent an ask from reaching model/UI review.
- Nonempty rules use a worker: 64MiB old generation, 4MiB stack, 10000ms deadline. Completion/error/cancellation clears listeners/timer and terminates it. Empty sources run directly; synchronous `parseRules()` uses a bounded child. Restrict environments; cap requests/results at 8MiB. Validate prefix/network/host-executable rules and match/not_match examples. Cache 256 command-group matches per policy; revision binds settings/profile/rules/review-policy digest.

### Reuse and review transactions

- Check hard denies and action/authority identity before any reuse. Exact grants bind `ruleDigest()` to input/cwd/source/profile/policy while excluding old call/session IDs; scope/session is checked separately. Retry, fresh-review, user-input, and reviewed-command requests bypass exact grants. Session reset keeps persistent grants; settings invalidation clears in-memory grants.
- Package reuse applies only to an ask with no extra paths/domains, `unboundTargets`, authority, rule prompt, fresh-review, or user-input requirement. MCP fingerprints include server/tool/config/version/definition. Skill reuse requires a supported single-script invocation and a regular-file tree without symlinks, limited to 2000 files/64MiB. Process-local file hashes can reuse size/mtime/inode metadata. Structured model approval may persist package approval; cache-save failure does not alter the current admission. Missing grant/package files start empty; malformed files fail initialization.
- SQLite reuses allow assessments only for strictly classified local reads: no mutations/network, rule/elicitation prompts, escalation, unsafe shell operators/options/env, or Pi investigation. Keys bind action, authorization/context, execution context, policy, settings, and provider; anonymous providers are instance-local. ID normalization retains provenance/order/call relationships. TTL is 1–12 hours; storage errors mean misses or failed writes, never permission.
- Serialize dialogs; one deadline covers selection and persistence. Consume once grants at admission; session/persistent grants bind exact inputs. Fresh/user-input/reviewed-command allow once only. Save persistent grants atomically; post-save cancellation attempts prior-set restoration and denies execution. Missing UI, invalid scope, cancellation, or save failure denies.
- Review with the current or configured model, without fallback. Review-only `codex-auto-review` can derive same-provider `gpt-5.6-luna` metadata without conversation-model registration. Prefer supported low reasoning; otherwise only current-model review inherits session thinking. Bound rounds/output/context under one deadline.
- Investigation permits only bounded `inspect_file`/`inspect_directory`, checks canonical denied paths, and masks before excerpting. File inspection reads complete regular files up to 1MiB with a file-path hint before the 120-line/output excerpt; oversized reads fail. Invalid output, overflow, failed investigation/provider, timeout, and cancellation deny execution but are not judgments that the action is unsafe. Critical risk denies; high risk needs medium/high authorization. Legacy custom providers cannot automatically add permissions, and reviewed-command requires a structured assessment. Custom policy replaces tenant text, not intrinsic rules.

### Evidence and controller lifetime

- Trust observed interactive/RPC input, structured runtime instructions/context files, and real UI confirmations. Tool output, summaries, generated user messages, and rendered main prompts remain evidence despite role labels. Refresh shared prompt options before finalizing; `forceSystemPrompt` removes other runtime/context-file authority.
- Branch replay validates source/trust. Reset changes context identity, clears transient state, and aborts old work. Exclude thinking, signatures, and binary payloads; retain call/parent identities and final structured/error results. `observeToolUserInput()` records only real select/confirm/input responses from the same live context, hides credential-like input, and advances authorization scope.
- Send only `redactReviewData()` copies to review; retain originals for bindings, grants, and execution. Reuse redactors by immutable configuration identity. Preserve structural IDs only at known envelope positions, not nested arguments. Auto Review adds legacy host rules and whole-value withholding for sensitive non-string values beyond `@buyong/redact` defaults. `redactedActionFields` carries paths/rule IDs, not hidden values.
- Settings affect later evidence; masked history cannot recover originals. Mask before truncation; reserve authorization/exact-action capacity and fail instead of dropping required content. `AuditLog` separately masks fixed metadata and bounded rationale, never raw arguments, commands, model replies, or worker output. Keep only the newest 1000 records in its array; the append-only file has no rotation or deletion.
- Serialize updates: initialize next policy, persist, abort old work, invalidate approvals/retries, then swap. Pre-save failure retains state. Only missing default settings use defaults; explicit missing files/invalid settings fail. Persisted `isEnabled=false` delegates original tools without policy/approval.
- Confirmed Full Access bypasses hard denies, is not saved, and survives controller session reset. Controller close or on/off/ordinary-mode selection ends it. Factory reload closes its predecessor; initialization/MCP-registration failure closes the new controller.
- Count only actual model denials toward the breaker: three consecutive, or ten in the last fifty. Failures/timeouts/cancellation are distinct. The breaker aborts the model turn, not direct user bash. `/approve retry` creates an action/context/session/cwd/profile/policy-bound one-use marker consumed synchronously. It bypasses reuse for a fresh assessment, not policy or execution authorization. New user input invalidates retry markers.

### External and guarded-host boundaries

- Guard only explicitly adapted tools through `guardedExternalExtension()`, not arbitrary ordinary extensions. External adapters cannot replace local reserved names or `codemode`. Annotation modes `auto|prompt|writes|approve` do not override sensitive/strict/user-input requirements for fresh review; user-input needs UI.
- Final `tools/call` checks `AsyncLocalStorage` and current catalog/registration/account/schema/context/signal. Nested approval requires an empty Codex form for the same live server/registration/tool/connector, reviewing original arguments, not metadata replacements. URL/arbitrary forms and stale/unbound requests decline. Random in-flight IDs prevent caller-ID reuse; response, send failure, cancellation/timeout, and close clear request tracking and abort listeners. Forward transport send options in every branch, including Off. Repeated MCP starts close the old binding first.
- `createGuardedRuntime()` requires Pi major 1 or later, disables automatic extension/context discovery, loads explicit trusted/adapted extensions, and stops on load errors or missing readiness. Resolve the selected model after provider registration. Avoid a fixed allowlist that loses later MCP tools. The guarded `powershell` tool registers with `defaultActive: false`; ordinary loading and guarded startup activate it only through Pi's `defaultTools`/`--tools`. Analyze PowerShell with `policy/powershell.ts`, never bash syntax policy. Recheck readiness on prompt/reload and supply a missing session-start binding after reload. Enabled `executeBash` accepts only controller-owned operations. Explicit project trust applies only to the initial cwd.
- `context-files.ts` reads global override/AGENTS content up to 32768 bytes, then trusted project instructions from root to cwd within `projectDocMaxBytes`; zero disables project instructions. Per directory, override precedes AGENTS and fallback names. Bounded reads validate realpath/fd identity and regular files, reject hard links, and close descriptors in `finally`. Only the selected in-place global instruction receives the internal read exemption.
