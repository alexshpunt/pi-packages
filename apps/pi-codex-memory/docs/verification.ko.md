# 검증·성능 결과

[English](verification.md) | **한국어** | [README](../README.ko.md)

Codex memory v2를 Pi에 접목한 뒤 확인한 결과입니다. 메모리 사용 전후의 회상, 압축 후 보존, 토큰 사용량을 다룹니다. 검증한 사례의 결과이며 일반적인 모델 순위는 아닙니다.

## 검증 범위

실모델 비교에는 저장된 16턴 합성 대화와 두 모델을 사용했습니다.

- **Haiku:** `claude-bridge/claude-haiku-5-5`
- **Luna:** `openai-codex/gpt-6-luna`

추론 강도는 Haiku 대화·조회에 `medium`, 추출·통합에 `low`·`medium`을 요청했습니다. Luna는 모두 `high`였습니다.

환경은 macOS, Pi 1.4.0, Node.js 24.14.0입니다.

1턴은 사용자 입력과 모델의 최종 답변 한 쌍입니다. 비교 조건마다 질문 한 건에 대한 답을 확인했습니다. 여러 번 실행한 평균은 아닙니다.

**이전 구현**은 압축된 대화를 추출 입력으로 사용합니다. **수정 구현**은 활성 분기의 원래 근거를 추출에 보존합니다. 두 구현은 정리한 Haiku 사본과 압축 후 추가한 턴을 포함해 모델별로 같은 입력을 받았고, 기억을 실제로 재생성했습니다. 조회는 질문에 정답을 넣지 않은 새 세션에서 수행했습니다.

실모델 결과는 저장소 공유 기능을 추가하기 전의 것입니다. 이후 저장소 공유 구현의 검사는 별도로 구분합니다. Codex CLI와 이 확장의 성능을 직접 비교하지는 않았습니다.

## 메모리 사용 전후의 회상

서비스, 지역, 검증 명령, 배포 게이트, 결정의 적용 범위, 과거 실행 여부 등 여섯 항목을 확인했습니다.

| 모델 | 메모리 미사용 | 이전 구현 | 수정 구현 |
| --- | --- | --- | --- |
| Haiku | 0/6 회상. 모두 모름 | 6/6 | 6/6 |
| Luna | 0/6 회상. 모두 모름 | 의미상 6/6 | 6/6 |

미사용 대조군이 모른다고 답한 것은 예상된 결과이지 모델 실패가 아닙니다. 수정 구현의 두 사례 모두 실제 기억 읽기와 유효 인용을 확인했습니다. **미사용보다 사실 여섯 개를 더 회상**했지만, 이 비교에서 이전 구현보다 정확도가 높았다는 뜻은 아닙니다.

Luna의 이전 답변은 “이 프로젝트에만 적용”이라는 동의 표현을 썼습니다. 원래 영어 문자열 검사는 **5/6**으로 판정했고, 별도의 의미 판정에서 같은 범위로 인정했습니다. 원래 판정은 바꾸지 않았습니다.

### 추출에 남은 원래 근거

| 모델 | 이전 구현 | 수정 구현 | 변화 |
| --- | ---: | ---: | ---: |
| Haiku | 원래 사용자 발언 0/16개 | 16/16개 | +16개 |
| Luna | 원래 사용자 발언 1/16개 | 16/16개 | +15개 |

수정으로 개선된 것은 **원래 근거의 보존**입니다. 이 수치가 모든 세부 내용의 저장이나 대화 전체의 영구 보존을 뜻하지는 않습니다. 기억 요약을 만드는 것과 올바르게 답하는 것은 별개의 결과입니다.

## 압축 후 기억 보존

앞선 실험의 여섯 사례에서 두 모델 모두 **압축 전과 직후에 6/6을 회상**했습니다. 기존 저장 기억은 유지됐지만, 압축된 대화로 기억을 다시 만들 때는 결과가 달랐습니다.

| 모델 | 6턴 후 재생성 | 16턴 후 재생성 | 32턴 후 재생성 |
| --- | --- | --- | --- |
| Haiku | 조회 재검사 후 6/6 | **2/6** | 입력 상한 512 KiB에서 6/6 |
| Luna | 재검사 후 사실·인용 일치. 범위는 동의 표현 | **0/6** | 상한 512 KiB에서 내용·인용 일치. 답변 표식 형식은 실패 |

16턴 실패에서는 값이 새 기억에 남아 있었지만, 확정된 결정을 미검증 정보로 다시 서술했습니다. 다음 모델은 이를 읽고도 모른다고 답했습니다. **값이 저장됐다는 사실만으로 회상 성공을 판단할 수는 없습니다.**

후속 수정 비교는 입력을 정리하고 새 후속 턴을 추가했습니다. 그 성공이 이전 실패를 없애거나 수정만으로 정확도가 향상됐다는 증거가 되지는 않습니다.

6·16턴은 실제 수동 압축, 32턴은 임계값을 낮춘 실제 자동 압축을 사용했습니다. 긴 입력은 기본 생성 예산 **256 KiB**를 넘었으므로 실험에서는 **512 KiB**를 썼습니다. 거부된 시도에서는 생성 요청을 보내지 않았습니다. 제품 기본값은 그대로이며, 기본 문맥 한도를 가득 채운 시험은 아닙니다.

## 토큰 사용량

16턴의 이전·수정 구현 비교에서 측정한 값입니다. 입력·출력·캐시 읽기·캐시 쓰기를 합산했고 Pi에 기록된 `totalTokens`와 일치했습니다. **토큰 수는 가격이 아닙니다.**

| 모델·작업 | 이전 토큰 | 수정 토큰 | 변화 |
| --- | ---: | ---: | ---: |
| Haiku 생성 | 13,184 | 38,632 | +25,448 (+193.0%) |
| Luna 생성 | 5,603 | 21,822 | +16,219 (+289.5%) |
| Haiku 조회 한 번 | 31,191 | 14,040 | −17,151 (−55.0%) |
| Luna 조회 한 번 | 8,088 | 10,940 | +2,852 (+35.3%) |
| Haiku 생성 + 조회 한 번 | 44,375 | 52,672 | +8,297 (+18.7%) |
| Luna 생성 + 조회 한 번 | 13,691 | 32,762 | +19,071 (+139.3%) |

생성에는 추출·통합을 셉니다. 조회에는 질문 한 건에 답하기까지의 모든 모델 호출을 포함합니다. 원래 대화 생성, 압축, 실행기 준비 실패, 이전 실패 조회, 정정·잊기는 제외합니다.

메모리 미사용 질문은 Haiku **3,453토큰**, Luna **1,156토큰**을 썼지만 모른다는 답을 받았습니다. 같은 정보를 성공적으로 조회한 저비용 사례로 비교할 수는 없습니다.

생성은 모델·구현별 호스트 요청 2회였습니다. 조회 요청은 **Haiku 3 → 2회**, **Luna 3 → 4회**로 달라졌습니다. 원래 근거를 더 보존하면서 생성 입력은 늘었고, 조회 토큰이 일관되게 줄지는 않았습니다.

## 관측 호출 시간

| 모델·작업 | 이전 | 수정 | 변화 |
| --- | ---: | ---: | ---: |
| Haiku 생성 | 27.795초 | 20.829초 | −6.966초 |
| Luna 생성 | 16.703초 | 18.922초 | +2.219초 |
| Haiku 조회 | 14.710초 | 10.261초 | −4.449초 |
| Luna 조회 | 7.488초 | 11.044초 | +3.556초 |

토큰 표와 같은 모델 호출의 호스트 기록 시간을 합산했습니다. 호출 사이의 대기, 그 밖의 도구 처리, 준비 시간은 제외합니다. **전체 UI 응답 시간이나 평균값이 아닙니다.** 캐시 상태·출력 길이·공급자 부하를 통제하지 않았으므로 수정이 속도 향상의 원인이라고 단정할 수 없습니다.

## 정정과 잊기

- 수정 구현의 두 사례 모두 정정한 내용을 재생성하고 새 세션에서 정정된 값을 포함한 여섯 항목을 회상했습니다.
- 잊기와 실제 압축 후 활성 기록 0개·잊은 사실 검색 0건·주입 0바이트를 확인했습니다. 유휴 조건을 충족한 뒤 다시 검사해도 기억을 재생성하지 않았습니다. `/codex-memory run`으로 실행한 검사이며, 이때 자동 타이머의 동작을 시험하지는 않았습니다.
- **최종 모델 답변 검사는 실패했습니다.** 빈 저장소에는 파일도 없어야 한다는 잘못된 질문이 원인이었습니다. 실제로는 빈 `memory_summary.md` 서식이 남을 수 있습니다. 수정한 질문은 재실행하지 않았으며, 오프라인 부재 검사가 이를 대신하지는 않습니다.

앞선 터미널 검사에서는 새 세션 회상, UI 정정·잊기, 취소, 재시작·재로드도 확인했습니다. **90초** 자동 재스캔 관찰 동안 잊은 값은 나타나지 않았습니다. 이 검사는 저장소 공유 이전의 것이며, 취소가 공급자 측 연산·과금 중단까지 입증하지는 않습니다.

## 저장소 공유 구현의 검사

이후 추가한 저장소 공유 구현은 격리된 저장소·합성 Git 메타데이터·가짜 스트림과 실제 Pi SDK로 검사했습니다. 새 실모델·터미널 실험은 아닙니다.

| 검사 | 결과 |
| --- | --- |
| 소스 테스트 | 81/81 통과 |
| 독립 설치본 | 리소스 로딩 통과. 저장소 41/41, 도구 6/6 |
| 번들 설치본 | 리소스 로딩 통과. 저장소 41/41, 도구 6/6 |

41개 사례는 81개 사례의 부분집합입니다. 공유·격리, 읽기 동의, 기존 기억 가져오기, 범위별 인용, 잊기, 동시 실행 경계를 확인합니다. 실모델 답변 품질을 입증하는 검사는 아닙니다.

## 한계와 로컬 확인

- 소수의 합성 사례이며 장기 실사용이나 다른 모델·운영체제의 결과를 보장하지 않습니다.
- 이전 압축 응답 한 건에 호스트 입력에서 찾을 수 없는 식별자가 있었습니다. 최종 기억에는 없었으며 출처는 여전히 모릅니다. 마스킹과 호스트 검사는 공급자의 완전한 격리를 증명하지 않습니다.
- 잊기는 원래 대화·백업·공급자 사본까지 지우지 않습니다. 독립된 출처에 같은 사실이 남을 수 있습니다.
- 과거 요청·응답 원자료는 공개 패키지에 포함하지 않습니다. 이 문서는 집계 결과이며 자체 완결된 실모델 재현 데이터셋은 아닙니다.

모델 호출 없는 테스트는 [README의 검증 명령](../README.ko.md#검증)을 참고하세요. `benchmark`는 합성 스케줄링 데이터이며 위 실모델 토큰·호출 시간 측정과 다릅니다.
