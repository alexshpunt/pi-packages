# 메모리 대기 시간과 보존 정책

## 선택한 초기값

- 추출 최소 유휴 시간: **30분** (`minIdleMs = 1800000`)
- 통합 최소 간격: **60분** (`consolidationCooldownMs = 3600000`)
- 작업 확인 간격: 60초. 전경 작업 중에는 처리하지 않는다.
- 조회 캐시 TTL: 사용하지 않는다. SQLite 상태와 변경 세대를 확인한다. 요청에 넣는 요약은 한 사용자 실행 동안 고정하되 정정·잊기·만료·설정 변경은 즉시 무효화한다.
- 미사용 기억 보존: 30일. 고정 기록은 제외하며 명시적 만료는 고정 여부와 관계없이 적용한다.

30분·60분은 아래 합성 패턴을 바탕으로 선택한 **조정 가능한 초기 절충값**이다. 실제 사용자 대화·모델 품질·비용·프롬프트 캐시 적중률을 측정한 보편적 최적값이 아니다.

## Codex의 6시간은 캐시 보존 기간이 아니다

기준은 Codex 커밋 `4610b573e59b211bf9430cf6ffb97cfb84623090`이다.

1. [config/src/types.rs](https://github.com/openai/codex/blob/4610b573e59b211bf9430cf6ffb97cfb84623090/codex-rs/config/src/types.rs#L57)의 `DEFAULT_MEMORIES_MIN_ROLLOUT_IDLE_HOURS = 6`: 마지막 대화 활동부터 추출 대상이 되기까지의 시간이다. 같은 파일의 설정 설명에는 12시간 초과를 권장한다는 주석도 있다. 기본값과 주석을 동일한 최적화 결론으로 해석하면 안 된다.
2. [state/src/runtime/memories.rs](https://github.com/openai/codex/blob/4610b573e59b211bf9430cf6ffb97cfb84623090/codex-rs/state/src/runtime/memories.rs#L26)의 `PHASE2_SUCCESS_COOLDOWN_SECONDS = 6 * 60 * 60`: 통합 성공 이후 다음 통합까지의 간격이다.
3. 미사용 기억의 30일 보존, 추출 대상의 최대 나이, 모델 공급자의 프롬프트 캐시 보존은 별도 정책이다. 이 확장은 공급자의 캐시 수명이나 요금을 바꾸지 않는다.

## 합성 비교

저장소 루트에서 실행한다. 모델·네트워크·개인 세션을 사용하지 않는다.

```sh
pnpm --filter @buyong/pi-codex-memory build
pnpm --filter @buyong/pi-codex-memory benchmark
```

`verification/timing.mjs`는 연속 작업, 짧은 중단, 검토 대기, 점심 뒤 재개, 2시간 간격 작업이라는 다섯 패턴을 1분 간격으로 계산한다. 실제 구현의 `isSourceEligible()`을 사용한다.

| 추출 대기 | 총 추출 횟수 | 마지막 활동 전 중간 추출 | 최종 활동 후 추출 대기 |
|---|---:|---:|---:|
| 5분 | 22 | 17 | 5분 |
| 15분 | 13 | 8 | 15분 |
| **30분** | **9** | **4** | **30분** |
| 60분 | 8 | 3 | 60분 |
| 6시간 | 5 | 0 | 6시간 |

중간 추출이 모두 낭비라는 뜻은 아니다. 긴 작업의 진행 상황을 일찍 기억하는 이익도 있다. 이 패턴에서 30분은 15분보다 호출을 줄이면서, 60분보다 최종 기록을 30분 빨리 준비한다.

통합은 2시간 동안 10분마다 자료가 추가되는 별도 패턴으로 비교했다.

| 통합 간격 | 통합 횟수 | 마지막 입력의 반영 지연 |
|---|---:|---:|
| 15분 | 9 | 0분 |
| 30분 | 5 | 0분 |
| **60분** | **3** | **0분** |
| 180분 | 2 | 60분 |
| 6시간 | 2 | 240분 |

마지막 입력 시점과 통합 시점이 일치해 0분이 나온 행이 있다. 일반적으로 새 자료는 다음 통합까지 최대 설정 간격을 기다릴 수 있고, 여기에 전경 작업·호출 예산·실패 재시도·프로세스 종료의 영향이 더해진다. 이 계산은 모델 실행 시간이나 일일 예산을 시뮬레이션하지 않는다.

## 운영 중 조정

`/codex-memory → 설정`에서 수정한다. `상태·사용량`에서 호출 수·실패·입출력 토큰·공급자가 보고한 비용을 확인한다.

- 긴 검토 중 중간 추출이 잦으면 추출 대기를 60분으로 늘린다.
- 다음 작업에 기억이 너무 늦게 나타나면 15분을 시험하되 호출 수와 정정 부담을 함께 확인한다.
- 비용을 우선하면 통합 간격을 180분 또는 6시간으로 늘린다.
- 즉시 반영이 필요하면 `/codex-memory extract` 또는 `/codex-memory run`을 사용한다. 사용자 확인 후 통합 간격을 건너뛴다. `extract`는 현재 분기의 유휴 대기도 생략하지만 `run`은 유휴 조건을 충족한 세션만 스캔한다. 중복·잠금·삭제 제외·일일 예산은 우회하지 않는다.

정정·잊기는 통합 모델을 기다리지 않고 기존 주입과 조회에서 제거한다. 새 통합 요약 생성에는 모델 접근이 필요할 수 있다. 읽기 중지와 자동 생성 중지는 서로 독립적이다.
